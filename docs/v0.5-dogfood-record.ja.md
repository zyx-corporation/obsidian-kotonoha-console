# v0.5 dogfood record（Obsidian Console）

Status: complete for v0.5.0.

## Phase 1 — review destination model and local-only UX

Review Destination は、RDE review output の「次にどこへ渡すか」を明示するためのモデルである。v0.5 では `Local only` を唯一の available destination とし、GitHub 系の出口は phase ごとの明示操作として扱う。

確認済み:

- `local_only` が既定の review destination。
- GitHub Issue / PR / commit annotation は planned handoff としてモデル化される。
- すべての destination で canonical record は `local_sidecar`。
- UI は「sidecar / note history が Kotonoha の記録で、GitHub は明示的な引き渡し先」と表示する。

Verification:

- `npm test -- reviewDestination consoleI18n`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 2 — copy or insert RDE summary block into current note

RDE summary block は、レビュー結果をノートへ戻すための local-first な引き渡し形式である。これは GitHub 投稿ではなく、ユーザーが自分のノート履歴へ意味監査の要点を戻す操作である。

確認済み:

- Proposal / RDE audit から `kotonoha review-handoff v0.5` summary block を生成できる。
- Summary block には file、proposal id、source hash、recommended decision、categories、risk sections を含める。
- Copy action で summary block をクリップボードへ送れる。
- Insert action で現在の対象ノート末尾へ summary block を追記できる。

Verification:

- `npm test -- reviewHandoff`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 3 — GitHub Issue draft text from RDE categories

Issue draft は、RDE review を GitHub Issue へ持ち込むための copy-ready text である。v0.5 では投稿は行わず、ユーザーが明示的にコピーして貼り付ける。

確認済み:

- Issue title/body draft を生成できる。
- Draft は file / proposal / source hash / category と review summary を含む。
- Draft は「Issue は publication/review handoff であり、Kotonoha の canonical record は local sidecar / note history」と明記する。
- ネットワーク投稿は行わない。

Verification:

- `npm test -- reviewHandoff`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 4 — link existing GitHub Issue and PR references

既存 Issue / PR reference は、RDE review と GitHub 上の会話を結ぶ correlation metadata である。これは意味の正本ではない。

確認済み:

- Issue URL、`owner/repo#123`、`#123` を Issue reference として認識できる。
- PR URL、`owner/repo!123`、`!123` を PR reference として認識できる。
- Issue field に PR reference を入れた場合、または PR field に Issue reference を入れた場合は invalid として表示できる。
- 認識された reference は summary block / Issue draft / PR summary に含められる。

Verification:

- `npm test -- reviewHandoff consoleI18n`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 5 — prepare PR summary for publication handoff

PR summary は、RDE review の観点を PR description に持ち込むための copy-ready text である。PR 自体を Kotonoha の semantic authority にはしない。

確認済み:

- Proposal / RDE audit から PR summary を生成できる。
- Summary には semantic review、drift risks、unresolved elements、boundary、verification checklist を含める。
- Existing Issue / PR reference を summary に含められる。
- Copy action のみで、自動投稿は行わない。

Verification:

- `npm test -- reviewHandoff`
- `npm test`
- `npm run typecheck`
- `npm run build`
