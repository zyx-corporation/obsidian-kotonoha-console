# v0.4 dogfood record（Obsidian Console）

Status: Phase 1–4 complete / Phase 5+ pending.

## Phase 1 — passive-observing git mode

`passive-observing` は、vault が Git worktree 内にある場合に Git の現在地を読むためのモードである。Kotonoha Console は branch、commit、dirty/clean、Git root から見た note path を表示できるが、Git の状態は変更しない。

確認済み:

- Settings で `passive-observing` を選択・保存できる。
- Git-backed vault では branch / commit / dirty state / repo-relative note path を context に含める。
- 非 Git vault では note path を残して graceful degrade する。
- 実行する Git command は `rev-parse` と `status --porcelain` の read-only 系に限定する。
- commit / pull / push / stage / unstage / reset / merge / rebase / checkout / switch / restore は呼び出さない。

Verification:

- `npm test -- gitReadonly gitContextLines obsidianGitDetect`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 2 — revise → re-audit → apply edge cases

改訂フローでは、提案本文・監査結果・適用本文が同じ意味対象を指していることを明示的に守る。

確認済み:

- Re-audit は現在表示中の revised proposal text を監査対象にする。
- Source hash が生成時から変化している場合、apply 前に確認を挟む。
- `obsidian-git-aware` では生成時から Git HEAD が変化している場合、apply 前に確認を挟む。
- 最後の監査後に revised text がさらに編集された場合、apply 前に再監査推奨の確認を挟む。
- Revised text が元 proposal と異なる場合、review decision は `partially_applied` になる。

Verification:

- `npm test -- revisionAuditGuards proposalService approvalService noteIoGuards consoleI18n`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 3 — partial apply UX

v0.3 の selection apply guard を維持しつつ、ユーザーが apply 前に適用範囲を理解できるようにする。

確認済み:

- Proposal UI に whole-note apply / selection apply の scope を表示する。
- Selection apply では選択テキストの文字数を表示する。
- Confirm dialog は whole-note と selection で文言を分ける。
- 将来の unsupported partial apply state は明示的に blocked state として表現できる。
- Selection が現ノート内に見つからない場合、whole-note fallback せず apply を中止する既存 guard を維持する。

Verification:

- `npm test -- applyScope applyNoteContent noteIoAcceptance noteIoGuards consoleI18n`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 4 — Git-enabled `context export`

CLI backend は、read-only Git snapshot が取れている場合にだけ `kotonoha context export` を使う。Git context がない場合は path + source hash anchor に戻し、Git state は変更しない。

確認済み:

- `gitMode = off` では `context export` を呼ばない。
- `gitMode ≠ off` かつ Git commit snapshot がある場合に `context export` を呼ぶ。
- 非 Git vault / Git snapshot 不在では `context export` を呼ばず、local anchor に degrade する。
- `context export` が失敗した場合も local anchor に fallback し、uncertainty note に失敗を表示する。
- CLI version が古い場合は実行前に actionable error を返す。
- Proposal body には Git anchor または path + source hash evidence を表示する。

Verification:

- `npm test -- cliKotonohaClient proposalFromContextPack buildNoteContext gitReadonly`
- `npm test`
- `npm run typecheck`
- `npm run build`
