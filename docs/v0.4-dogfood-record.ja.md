# v0.4 dogfood record（Obsidian Console）

Status: Phase 1–2 complete / Phase 3+ pending.

## Phase 1 — passive-observing git mode

`passive-observing` は、vault が Git worktree 内にある場合に Git の現在地を読むためのモードである。Kotonoha Console は branch、commit、dirty/clean、Git root から見た note path を表示できるが、Git の状態は変更しない。

確認済み:

- Settings で `passive-observing` を選択・保存できる。
- Git-backed vault では branch / commit / dirty state / repo-relative note path を context に含める。
- 非 Git vault では note path を残して graceful degrade する。
- 実行する Git command は `rev-parse` と `status --porcelain` の read-only 系に限定する。
- commit / pull / push / stage / unstage / reset / merge / rebase / checkout / switch / restore は呼び出さない。

Verification:

- `npm test -- gitReadonly gitContextLines obsidianGitDetect`
- `npm test`
- `npm run typecheck`
- `npm run build`

## Phase 2 — revise → re-audit → apply edge cases

改訂フローでは、提案本文・監査結果・適用本文が同じ意味対象を指していることを明示的に守る。

確認済み:

- Re-audit は現在表示中の revised proposal text を監査対象にする。
- Source hash が生成時から変化している場合、apply 前に確認を挟む。
- `obsidian-git-aware` では生成時から Git HEAD が変化している場合、apply 前に確認を挟む。
- 最後の監査後に revised text がさらに編集された場合、apply 前に再監査推奨の確認を挟む。
- Revised text が元 proposal と異なる場合、review decision は `partially_applied` になる。

Verification:

- `npm test -- revisionAuditGuards proposalService approvalService noteIoGuards consoleI18n`
- `npm test`
- `npm run typecheck`
- `npm run build`
